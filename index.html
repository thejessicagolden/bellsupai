Color System

Navy functions as the primary emphasis color and carries the greatest visual authority within the system. Slate and Dust support hierarchy, layering, and interface structure, while Glacier Gray provides a neutral supporting tone. Cloud serves as the primary background color and creates spacious, low-noise environments. Light Tan and Taupe introduce warmth without increasing saturation. Graphite provides structural contrast, while Charcoal is reserved for high-emphasis surfaces and dark applications.

Accessibility

Contrast Standards

WCAG AA minimum — 4.5:1 normal text · 3:1 large text

  • Navy on Cloud#142636 on #F0EEE9 · ~14.4:1 · AAA ✓
  • Charcoal on Cloud#101720 on #F0EEE9 · ~16.8:1 · AAA ✓
  • Graphite on White#52524F on #FFFFFF · ~7.6:1 · AAA ✓
  • Navy on White#142636 on #FFFFFF · ~16.7:1 · AAA ✓
  • Charcoal on Light Tan#101720 on #D9D1C2 · ~12.5:1 · AAA ✓
  • White on Navy#FFFFFF on #142636 · ~16.7:1 · AAA ✓
  • Dust on White#94A6B8 on #FFFFFF · ~2.3:1 · Fails — decorative use only
  • StandardWCAG 2.1 Level AA required · Level AAA where possible
  • Large text18 px bold or 24 px regular qualifies as large text
  • Non-textUI components and graphical objects require 3:1 minimum
  • ToolVerify with WebAIM Contrast Checker before deploying new combinations

Focus States

Specification

  • Style2px solid --color-navy
  • Offset2px · ensures visibility against all surfaces
  • Applies toAll interactive elements — buttons, links, inputs, selects
  • CSSoutline: 2px solid var(--color-navy); outline-offset: 2px;

Rules

  • NeverRemove focus outline without a visible alternative
  • NeverUse outline: none without replacing with custom focus style
  • Mouse usersUse :focus-visible to hide focus on mouse click only if needed
  • Dark surfacesUse white outline on navy/charcoal backgrounds

Semantic HTML

Landmark elements

  • <header>Site header and navigation
  • <nav>Primary and secondary navigation
  • <main>Primary page content · one per page
  • <section>Thematic grouping with a heading
  • <article>Self-contained content unit
  • <aside>Supplementary content
  • <footer>Site or section footer

Interactive elements

  • <button>Actions — submit, open modal, toggle
  • <a>Navigation — links to pages or anchors
  • <label>Every form input must have an associated label
  • <h1>–<h6>Hierarchical — never skip levels
  • aria-labelWhen visible label is absent
  • aria-labelledbyWhen label is a separate visible element
  • alt textRequired on all meaningful images

Keyboard Navigation

Key interactions

  • TabMove focus forward through interactive elements
  • Shift + TabMove focus backward
  • Enter / SpaceActivate button or link
  • EscapeClose modal, menu, or overlay
  • Arrow keysNavigate within dropdowns, menus, radio groups

Implementation rules

  • Tab orderMust follow logical reading order in the DOM
  • Focus trapModals must trap focus while open
  • Focus returnReturn focus to trigger element on modal close
  • Skip linkProvide "Skip to main content" as first focusable element
  • tabindexUse 0 to add to order · avoid positive values

Component Code Standards

Naming conventions

  • Block.component — the root element
  • Element.component-element — a part of the block
  • Modifier.component--variant — a state or variant
  • Example.card · .card-body · .card--flat
  • CasingLowercase · hyphen-separated · no underscores

Rules

  • TokensAlways use CSS variables — never hard-code colors or spacing
  • SpecificityKeep selectors flat · avoid deep nesting
  • ResponsiveAdd mobile overrides within the component's CSS block
  • AccessibilityInclude ARIA attributes and semantic HTML by default
  • Avoid!important · inline styles · element-only selectors for components
